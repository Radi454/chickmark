# ChickMark sampling implementation plan

Status: implementation and local verification completed; commit/push and Pages verification pending. The findings below describe the inspected pre-change baseline; the design remains authoritative. The user authorized implementation, review, commit/push, and GitHub Pages deployment without another approval.

## Pre-implementation baseline findings

- The app is offline-first: SQLite panel rows are the working store and Supabase mirrors them. The database is version 81. Schema upgrades must update `database_helper.dart`, `database_schema.dart`, `database_migrations.dart`, `_criticalColumns`, schema expectations, and Supabase push/pull/schema support together.
- Current audit persistence is panel-only. `AuditPanelSaveCoordinator` writes the configured measurement tables through `PanelSampleRepository`; audit reopening reads those panel rows and reconstructs station drafts in `audit_session_screen.dart`. `StationSampleRepository` is an empty compatibility stub and `station_samples` is obsolete. Do not restore it.
- `PanelSampleSchema` is the central panel table registry and currently records allowed layers plus hierarchy and measurement columns. Current allowed layers differ from the planning draft in places. The current entries include Fresh Egg Breakout Tray; the draft says Fresh Egg Breakout is House only. The draft scope matrix is the intended product configuration, so implementation should remove that extra Tray permission unless the parent/product review changes the source decision.
- Panel measurement rows already have immutable `id`, `sessionId`, and hierarchy columns, but the persistence builder mostly stores one `scopeType` (the deepest selected identity) and does not persist the full selected-versus-Pooled scope configuration. `sampleIndex` is a display/order field and is renumbered; it is not suitable as the permanent `SA` serial.
- `AuditProvider.setStationSampleMode` and `setChickWeightSampleMode` collapse samples when returning to Pooled. `removeActiveSample` will not remove the last comparison row and changes a lone survivor to Pooled; specialized Chick Quality and Chick Weights removal paths also turn the last comparison into Pooled directly. This contradicts the latest decision: comparison remains active with one item, and deleting that final item removes it and restores the default Pooled state.
- Panel-row removal uses `PanelSampleRepository` tombstones. `PhotoRepository.deleteByPanelRow` queues photo metadata tombstones and deletes local files, but currently has no callers. Supabase's `deleteRows('photos', ids)` also removes remote storage objects before deleting remote metadata. Local `photos.panelRowId` is not a foreign key to panel tables, so branch deletion must explicitly collect and tombstone photos and avoid deleting a backing file still referenced by another photo row. `SyncTombstoneRepository.deleteOrder` currently puts panel parents before the base `photos` entry; process photo tombstones before panel-row tombstones so remote object paths are captured before any server-side cascade can remove metadata.
- Dashboard panel queries use panel-table rows and scope fields, so they must be checked for full-path and Pooled semantics after the row model changes.
- Customer, hatchery, and flock models/schema do not currently contain the requested three-letter code fields. The shared code format in the draft is Customer-Hatchery-Farm-Breed-selected-scope-segments-SA. Existing rows need a migration default and the relevant create/edit forms need validated code entry. Existing IDs stay unchanged.
- Setter Optimizing and Hatcher Optimizing are already separate panel tables. Their hierarchy is currently only `setter` or `hatcher`; measurements include `incubationAgeDays` and `incubationHours`. Keep these age fields and their current behavior. Extend their scopes only to Setter/Trolley/Tray and Hatcher/Trolley/Tray respectively.
- `.github/workflows/deploy-pages.yml` deploys on every push to `main` and manual dispatch. A push to `main` is therefore the deployment trigger requested by the user.
- Existing unrelated repository changes observed: modified `analysis_options.yaml`, modified `ios/Podfile.lock`, and untracked `planning/`. Preserve them.

## Product rules to implement

- A sampling state is isolated by audit session and panel. Each panel uses the existing panel registry to declare its permitted scopes and terminal sample identity.
- Every applicable ancestor level starts Pooled. Selecting comparison identities creates branch tabs at that level and makes that level's Pooled entry inactive while identities exist. Users can edit identity fields. Deleting a branch deletes its descendants and associated measurements, photos, notes, and panel records after a clear localized confirmation; cancel is a no-op and siblings remain untouched.
- Deleting the final comparison item removes that item and restores the default Pooled state automatically. Keep Comparison as the mode while one comparison item remains. There is no convert-branch-to-Pooled action and no reassigning removed comparison measurements to Pooled.
- The first comparison branch added to a panel that already has measured Pooled data uses the approved reset confirmation; cancellation preserves existing data, confirmation deletes the Pooled sample data, then creates the named branch. Never relabel or copy the old data.
- Each saved leaf row stores its full applicable scope path, with each level represented as a selected identity or Pooled, plus a stable immutable Sample ID and a permanent visible `SA<n>` serial. The complete Pooled starting state is one sample: an identified Tray under Pooled ancestors for Tray panels, or one panel-native sample where Tray does not apply. Multiple descendant Tray samples may exist under an unscoped/Pooled intermediate ancestor. Panels without Tray retain their actual terminal sample type and must not acquire Tray samples as a side effect.
- Codes follow the draft's three-letter identity prefix, maintained breed abbreviation, selected scope segments in physical order (H/S/HT/TR/T), then `SA<n>`. Pooled scopes add neither number nor code segment. Editing registered codes or scope numbers regenerates the visible code without changing Sample ID or measurements.
- Confirmed panel scope matrix: Egg Storage (Pooled only); Egg Quality (House); Chick Quality (Setter + Hatcher together); Chick Weights (House); Fresh Egg Breakout (House); Candled Egg Breakout (House, Setter, Trolley, Tray); Residue / day-21 Breakout (House, Setter, Hatcher, Trolley, Tray); Setter Optimizing (Setter, Trolley, Tray); Hatcher Optimizing (Hatcher, Trolley, Tray). Preserve existing age-of-incubation behavior and other measurement behavior.
- Preserve station-specific uniqueness constraints, such as one Chick Quality sample per Setter-Hatcher pair in a session/panel. Registered House/Setter/Hatcher identities should be sourced from the existing flock/hatchery/machine records as appropriate.

### Storage and identity details

Add local `panel_sampling_states` (one row per session/panel) with `id`, `sessionId`, `panelKey`, `serialHighWatermark INTEGER NOT NULL`, timestamps, and standard dirty-sync fields. The synced high-watermark must merge by `max`, never last-write-wins. Add `panel_sampling_nodes` with columns `id TEXT PRIMARY KEY`, `sessionId TEXT NOT NULL`, `panelKey TEXT NOT NULL`, `parentId TEXT NOT NULL DEFAULT ''`, `level TEXT NOT NULL`, `identityKey TEXT NOT NULL DEFAULT ''`, `identityJson TEXT`, `sampleId TEXT`, `sampleNumber INTEGER`, `isTerminal INTEGER NOT NULL DEFAULT 0`, `createdAt TEXT NOT NULL`, `updatedAt TEXT NOT NULL`, and standard dirty-sync fields. Add append-only `panel_sample_serial_reservations(sessionId,panelKey,sampleNumber,sampleId,createdAt,syncStatus,dirtyAt,lastSyncedAt,syncError)`, unique by `(sessionId,panelKey,sampleId)` rather than sample number so independently allocated colliding numbers can both be recorded and reconciled; retain reservations after node deletion so serials are never reused. Each scope branch is one node row. A terminal scope node also owns `sampleId` and `sampleNumber`; a panel with no comparison scopes uses one terminal `sample` node under the root. No global JSON document holds the tree, so independent branch adds/deletes do not overwrite one another. Pooled ancestors are null in each terminal path and have no fake node.

Use unique index `(sessionId, panelKey, parentId, level, identityKey)` for comparison identities and `(sessionId, panelKey, sampleNumber)` for terminal samples. Add row-level `sampleId TEXT`, `sampleNumber INTEGER`, and `samplingPathJson TEXT` to panel measurement tables; measurement rows retain their existing `id`. `sampleId` references the terminal node's immutable ID; where the existing measurement row ID already is the same value, preserve it. All child observations and photo rows continue to reference the real measurement-row ID. Add corresponding remote columns/table, generated schema support, Supabase sync allowlists, upsert/delete mappings, pull handlers, tombstone registration, critical columns, and test schema expectations. Panel node rows sync independently and use existing per-row dirty timestamps; deleting a branch queues tombstones for descendants before their parent and for related measurements/photos in the same local transaction.

**Offline serial rule:** allocate locally monotonic positive integer serials from `serialHighWatermark + 1`; save every assigned number in the append-only reservation table, even after sample deletion. During pull/push, collect all colliding terminal rows and reservations for a session/panel; sort colliding sample IDs lexicographically, keep the contested number on the smallest ID, and give each other colliding sample the next unused number above `max(all synced high-watermarks, active node numbers, and reservations)`. Commit that reconciliation atomically on the sync path and upsert the updated number to both the node and measurement row before marking them synced. Never change `sampleId` or measurements; never renumber due to deletion or reordering. Apply the same rule on every device so pull/push order cannot change the winner. A globally sequential number cannot be guaranteed while devices are disconnected; locally allocated duplicates may be visible until sync resolves them. This is the offline-first tradeoff and the sole case where an existing `SA` label can change.

**State/provider bridge:** add to `AuditProvider` a map keyed by `(sessionId,panelKey)` and APIs `Future<PanelSamplingState> loadPanelSamplingState(String panelKey)`, `String activeSampleIdFor(String panelKey)`, `Future<void> selectPanelSample(String panelKey, String sampleId)`, `Future<void> addPanelScopeIdentity(String panelKey, SamplingScopeLevel level, String? parentId, Map<String,String> identity)`, `Future<void> editPanelScopeIdentity(String panelKey, String nodeId, Map<String,String> identity)`, `Future<SamplingDeletePreview> previewPanelScopeDeletion(String panelKey, String nodeId)`, and `Future<void> deletePanelScopeNode(String panelKey, String nodeId)`. Screen owns the confirmation dialog and calls delete only after affirmative confirmation; repository owns atomic persistence. Keep legacy `StationSampleModel` as a UI/form adapter during cutover: build it from the active leaf path and current `AuditModel` when station widgets need it, but do not persist mode or sample indices back as authoritative scope state. `AuditPanelSaveCoordinator` accepts the active leaf `sampleId` and `SamplingScopePath` for each `PanelSavePair` and passes them to `upsertMeasurementIdentity` in the same transaction as the panel row save. `audit_session_screen.dart` loads sampling state beside panel rows and selects the persisted/first valid leaf before provider initialization completes.

## Conservative rulings

1. **Adding the first comparison item when meaningful Pooled data exists:** resolved in the authoritative design. Confirm deletion; cancellation leaves state and data unchanged.
2. **Legacy code fields:** no existing codes exist, so do not fabricate. Preserve records and make full code display indicate missing code until the user supplies one. Code entry is optional for unrelated workflows and required only to render a complete standardized sample code.
3. **Logical sample versus measurement row cardinality:** current panel rows generally represent measured samples, but Chick Quality has normalized observations and breakout rows can have child records. Reuse panel row `id` as sample ID only where the one-row-per-sample relationship is verified; otherwise add an explicit sample identity key and preserve one Sample ID across its measurement/child rows.
4. **Remote panel sampling-state synchronization:** `panel_sampling_states`, `panel_sampling_nodes`, and append-only serial reservations are required synced tables, including when there are no measurement rows. They use per-row dirty tracking and tombstones; no measurement placeholder rows or whole-tree JSON replacement.

## Architectural risk

Offline devices cannot guarantee one globally sequential `SA1`, `SA2`, … sequence without server-issued serial blocks or a live allocator. Keep local numbers understandable and monotonic, reserve every consumed number, then apply the documented deterministic collision repair at sync. The only permitted label change is when two offline devices actually allocated the same number; the immutable sample ID and measurements remain fixed. If the product later requires every shown serial to be globally unique even before sync, it must choose online allocation or leased ranges, which conflicts with unrestricted offline sample creation.

- Do not implement sample averaging, merge removed comparison data into Pooled, or add a convert-branch-to-Pooled action.
- Do not reset other panels or audit sessions during a branch deletion.
- Do not add Tray to panels whose configured terminal identity is not Tray.
- Keep Setter/Hatcher incubation-age data and station measurement behavior intact.
- Preserve the observed unrelated `analysis_options.yaml`, `ios/Podfile.lock`, and untracked `planning/` changes.
